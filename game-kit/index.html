game-kit · our release pipeline

One command ships the next version to Google Play.

game-kit is how the EvolvAI team releases its Android games. A developer types one command in a game's repository, answers one question, and the new version is built, tested, signed and on Google Play's test track about fifteen minutes later.

Why we built it

Ship more games, with fewer mistakes

A new game costs one file

Each game describes itself in a short manifest. Building, signing, checking and uploading are shared, so an improvement reaches every game at once.

Anyone on the team can release

No release depends on one person's laptop. The same steps run the same way for every developer.

Nobody shares a login

Signing keys stay in the pipeline's encrypted storage. Each developer uses their own Google account with access only to the games they work on.

Mistakes stop early

A wrong version, missing notes or an invalid store answer stops the release in about a minute, before anything reaches Google Play.

The store page lives with the code

Store text and screenshots are files in the game's repository: reviewed like code, checked against Play's limits, published in one step.

Claude does the paperwork

Release notes, store-risk reviews and the Play Console forms that have no API, filled in the developer's own browser.

Before anything reaches Google Play

What every release checks

  • The release comes from the main branch and matches the app's version
  • The version number is new to Google Play
  • Release notes exist, within Play's length limit
  • Store answers use only fixed choices, never free text
  • Store text and images meet Play's sizes and limits
  • Every automated test passes
  • The build is signed with the game's own key
  • Native code meets Play's 16 KB page requirement
Guardrails

What stays with people

Production is never automatic

The pipeline can reach Google Play's test tracks only. Releasing to everyone is done by the account owner, by hand.

A yes before every submit

When Claude fills a Play Console form, it shows every value with a screenshot and waits for approval. It never types a password or solves a CAPTCHA.

Store answers are reviewed

Content rating, ads and data-safety answers live in a reviewed file. Claude types only what that file says.

Tested before players

Every new game runs a closed test with real testers before it can go to production, as Google requires.
